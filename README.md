# 公文写作与交付

面向中文公文和正式材料的写作 skill，覆盖起草、改稿、审稿、摘要压缩、公文格式适配和 Word 文件交付。把会议记录、工作要点、参考旧稿和零散数据整理成完整文稿，根据文种、读者、单位模板和实际用途调整内容与版式。

可供 Codex、DSH 等支持 Agent Skills 的 AI 助手使用。核心写作能力无需安装依赖，附带本地文本检查与 Word 工具。

## 覆盖的文体

| 文体 | 重点解决的问题 |
| --- | --- |
| 情况报告、工作汇报、工作总结 | 讲清进展、做法、成效、问题和后续安排 |
| 请示、专题签报、改革建议 | 说清请求事项、理由、实施条件和需要决定的问题 |
| 通知、函、答复、公开说明 | 交代对象、事项、条件、时间和办理路径 |
| 工作意见、实施方案 | 把目标落实为任务、责任、节点和推进措施 |
| 调研报告、政策研究材料 | 从材料中形成发现，解释原因，提出有依据的建议 |
| 讲话、讲话提纲、会议纪要 | 按场合组织表达，提炼重点，准确记录议定事项 |
| 经验交流、党建及基层工作材料 | 写清具体做法怎样起作用、产生什么变化、有哪些适用条件 |

同一份材料也可以面向不同读者改写：给决策者突出判断和待决定事项，给执行人员写清动作和分工，给企业和公众说明条件、影响及办理方式。

## 主要功能

### 从零散材料到完整初稿

提供工作要点、会议记录、数据或几段背景，即可按用途组织正文。材料尚未收齐时，可以先写完整待补稿，保留 `XXX`、`XX万元`、空白或 `【待补】`，收到材料后继续补充。

已有事实、候选做法和下一步安排分别处理。工作情况尚未报送时，可按用户要求保留汇报体，不把缺少材料直接写成“尚未开展”。

### 参考旧稿，改出适合本次任务的稿子

参考稿可以用来借鉴结构、语气和通用做法，再结合本次职责和条件改写。旧稿中的年份、成绩、数字和政策状态与本期事实分开处理。

支持整篇重写、局部润色、调整结构、转换文种和改变受众。只要求修改一段时，就围绕该段处理；压缩时保留关键事实、适用条件、否定词和工作状态。

### 适配文种、读者和写作要求

同一批材料可按用途组织成报告、请示、通知、方案、讲话或其他正式材料，并调整标题、结构、详略和语气。面向机关负责人突出依据、选项和待决定事项；面向执行岗位写清任务、分工和节点；面向企业和公众解释条件、影响和办理路径。

可以按指定参考稿和本次反馈调整文风、篇幅及输出方式。用户要求先列提纲、只做审稿或只交正文时，采用相应的交付方式。

### 把分析和建议写具体

调研、签报和改革建议围绕“问题怎样产生、措施怎样起作用、实施需要什么条件”展开。文稿的层次和篇幅服从内容，标题、段落与分项方式根据实际论证安排。

表达上强调自然、连贯、具体，减少空泛评价和重复套话。已有准确数据和必要术语予以保留，面向非专业读者时补充解释。

### 审稿与事实、依据、数字核对

结合用户材料和实际可获取的来源，区分本期事实、历史背景、政策依据和风格参考，检查来源冲突、依据适用范围及待核事项。审稿先看事实、权限、数字和逻辑，再处理表达与格式，并针对原文给出可定位的问题及修改建议。

数字核对涵盖主体、期间、单位、分母、合计与分项、比例与百分点，以及正文和表格的一致性；同时保留“已完成”“拟开展”“待批准”等状态差异。待补稿与正式定稿分别检查，已允许的占位符可以继续保留。

### 摘要、篇幅压缩和汇报提纲

可将长材料整理成阅读摘要、决策摘要、短报告、汇报提纲或口头发言稿，按要求压缩到指定篇幅。优先删去重复、冗长背景和空泛评价，保留核心事实、结论、例外条件及待决定事项。

附带本地文本检查工具，可检查占位符、非空白字符数量、汉字数量、指定篇幅范围和完全重复的段落，帮助定位需要补充或精简的位置。

### 公文格式适配与单位模板

根据交付用途选择正式公文正文、内部签报与汇报材料、调研与研究报告的版式，适配纸张、页边距、标题与层级、字体字号、行距、段首缩进、表格和页码。结合文种核对主送、附件说明、署名及成文日期等要素。

独立 Word 工具提供三套可调整的版式预设：

| 版式 | 适用材料 | 主要配置 |
| --- | --- | --- |
| 公文正文 `government-body` | 正式公文正文 | A4、正文版心与页边距、三号仿宋、标题与层级字体、单双页外侧页码 |
| 内部汇报 `internal-report` | 签报、工作汇报、讲话等内部材料 | 仿宋正文、标题与层级样式、段落缩进、表格和居中页码 |
| 研究报告 `research-report` | 调研报告和较长分析材料 | 宋体正文、分级标题、报告页边距、表格及页码 |

可以通过自定义配置调整字体、字号、行距、缩进、边距和页码等参数。提供单位模板时，优先配合宿主已有的文档编辑能力沿用模板版式，保留本次正文；独立脚本负责按预设或自定义配置新建 DOCX。

公文正文预设用于基础排版，红头、印章、版记及字体的实际显示仍需结合单位模板和接收环境核对。详细格式规则见 [公文格式适配](references/document-format.md)。

### Word 生成、内容提取与交付检查

将确认后的标题、正文、普通表格、附件说明、落款和显式分页排成 DOCX；也可从受支持的已有 DOCX 中提取正文及表格，供阅读和核对。

生成后回读文件，与完整输入逐项比对文字、数字、段落顺序、表格单元格和显式分页位置，并检查工具已实现的基础版式参数。已有文件的修改保留原件或另存新版本。

本机具备 LibreOffice 时可生成 PDF 预览，另有 pdftoppm 时可导出逐页 PNG，辅助检查截断、异常空白、孤立标题、表格跨页和页码。复杂修订、文本框、图片、公式及合并表格等内容，结合宿主相应的编辑能力处理。工具与输入说明见 [Word 交付](references/docx-delivery.md)。

## 效果示例

以下均为虚构教学案例，用于展示处理方式。

### 示例一：材料未齐，先写待补报告

**任务：** 已印发便民服务工作要求，各地具体情况尚未报送。先起草目前做法和下步安排，具体事项及数字可以留空。

**稿件片段：**

> 已印发便民服务工作要求，明确填报范围和工作安排。围绕XXX事项，开展了XXX工作，梳理解决XX类问题；结合办理需求完善相关流程，累计办理XX件，服务XX人次。
>
> 下一步，收集各地工作情况，核对具体做法和成效，梳理可继续完善的环节，研究后续改进安排。

首句使用已知事实，其余内容作为待填或供核实选用的候选段落。先形成可继续修改的完整稿，后续按实际情况补充、删改。

### 示例二：把办理规则改成企业看得懂的说明

**原始材料：** 材料齐全并受理后，5个工作日内出具办理结果；需要补充材料的，应一次告知；补充材料所需时间不计入办理时限。是否符合办理条件须审查后确定。

**改写：**

> 材料齐全并受理后，将在5个工作日内出具办理结果。需要补充材料的，会一次告知；补充材料的时间不计入上述时限。申请能否通过，以审查结果为准。

用办事主体容易理解的表达保留起算时间、工作日、补充材料和审查条件，准确区分“出具结果”与“审批通过”。

### 示例三：局部压缩，保留条件和状态

**原文：**

> 拟在条件成熟的两个点位试行预约服务。未经批准，不向其他点位推广。服务对象范围还在研究，不能对外承诺全面开放。

**改写：**

> 拟选择两个条件成熟的点位试行预约服务，未经批准不扩大范围。服务对象尚在研究，暂不对外承诺全面开放。

减少重复表达，同时保留试行状态、点位数量、批准前提和未定范围。

更多成篇写法见 [教学示例](references/worked-examples.md)，可直接使用的请求见 [使用示例](docs/examples.md)。

## 如何使用

### 安装

下载 [Releases](https://github.com/perskill/gongwen-skill/releases) 中的 `draft-official-documents-v<版本>.zip`，解压后将完整的 `draft-official-documents` 文件夹放入 AI 助手的技能目录，保持 `SKILL.md` 与参考资料、脚本的相对位置。

Codex 可放在以下位置：

| 范围 | 位置 |
| --- | --- |
| 当前项目 | `.agents/skills/draft-official-documents/` |
| 当前用户 | `~/.agents/skills/draft-official-documents/` |
| Windows 当前用户 | `%USERPROFILE%\.agents\skills\draft-official-documents\` |

也可以下载仓库源码，将含有 `SKILL.md` 的根目录命名为 `draft-official-documents` 后放入对应位置。其他宿主的安装方式见 [跨工具使用](references/platforms.md)。

### 直接提出写作任务

说明文种、读者、篇幅、材料和交付要求即可：

```text
请使用 $draft-official-documents，根据以下材料起草一份约800字的工作情况报告。

读者：上级主管部门。
重点：目前进展、主要问题、下步安排。
要求：只交付正文；缺少的数字保留XX，可先写完整待补稿。
材料：……
```

改稿时可以指定范围：

```text
请使用 $draft-official-documents，把下面这段说明改成面向办事群众的通知。
保留时间、地点、办理条件和咨询渠道，只修改这一段。
原文：……
```

需要文件时直接说明：

```text
请使用 $draft-official-documents，将已确认正文排成内部汇报Word。
正文不作增删，生成后回读核对全文和表格，并说明页面检查情况。
正文：……
```

需要适配公文格式时，可以指定用途和模板：

```text
请使用 $draft-official-documents，将以下正文按正式公文正文格式交付Word。
采用government-body预设，调整标题、层级、正文、落款和单双页页码。
正文内容保持不变，生成后回读核对文字与基础版式。
如附有单位模板，优先结合可用的文档编辑工具按模板处理。
正文：……
```

通常按以下顺序完成任务：

```text
明确用途与读者 → 整理事实和参考材料 → 起草或修改 → 审稿核对 → 格式适配与文件交付
```

默认直接交付正文；要求先列提纲、只审稿或分阶段修改时，按指定方式处理。

### 本地辅助工具

纯文本写作无需 Python。需要运行文本检查时，使用 Python 3.9+：

```sh
python scripts/check_draft.py "正文.md" --json
```

需要生成 Word 时，先在 Python 环境中安装 `requirements.txt` 中的依赖，再运行：

```sh
python -m pip install -r requirements.txt
python scripts/gongwen_docx.py build --source assets/example-document.json --output "示例.docx"
python scripts/gongwen_docx.py verify --source assets/example-document.json --docx "示例.docx" --check-layout
```

完整输入格式、版式选项和页面预览方法见 [Word 交付](references/docx-delivery.md)。
